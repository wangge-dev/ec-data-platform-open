# 给 AI 的可复制提示词

给人看的安装步骤见 [USER_GUIDE.md](USER_GUIDE.md)，AI 工作规则见 [AI_DIY_GUIDE.md](AI_DIY_GUIDE.md)。第一次来，可以直接复制下面的「仓库交给 AI」提示词；后面的专项模板再按需填写方括号。只附脱敏样例，不附密码、`.env` 或数据库备份。

## 0. 把仓库交给 AI（直接复制）

不用先懂技术，也不用填完所有需求。复制整段到 ChatGPT、Codex 或其他 AI；如果你已经有目标，在末尾加一句「我想……」。

```text
请帮我使用这个开源轻量电商数据中台：
https://github.com/wangge-dev/ec-data-platform-open

默认目标：先在我的电脑上运行正式版本，用合成样例验证，再根据我的报表做 DIY。
先实际读取仓库 README、docs/GETTING_STARTED.md、docs/USER_GUIDE.md、
docs/AI_DIY_GUIDE.md 和 docs/AI_PROMPTS.md，核对最新正式 Release 与附件。
打不开就明确说明，请我提供对应文件，不要凭仓库名猜功能或步骤。

先确认你能否操作我的电脑，以及我的系统、处理器架构、Docker 状态，
有没有已安装的实例；只问会影响下一步的必要信息。
如果你只有网页访问能力，给我一次一个可执行步骤，等我反馈；
如果你有本机工具，在我授权的安装或开发范围内执行并检查结果。

安装优先使用正式 Release 的离线运行包，不把 Code / Source code ZIP 当安装包。
已有实例先按手册备份和升级，不覆盖数据、密码或自定义配置。
用合成样例检查健康、登录、上传、处理结果和图表；没实际执行的不要说已通过。
普通单表先用页面新建模块；复杂需求再取对应版本的完整源码，
阅读 AGENTS.md 和相关实现，依据脱敏样表、业务口径与人工答案做最小修改和测试。

不要让我把密码、API Key、完整 .env、真实客户数据或数据库备份发到聊天里；
不要清空数据卷，也不要自动把业务资料推送到 GitHub。
最后用小白能懂的话说明：做成了什么、还缺什么、我下一步做什么。
```

可在末尾追加：`我只想安装体验，不改代码。`、`我已经能打开网页，想接入自己的报表。` 或 `我想用 Codex 改一个具体功能：……`。

这段提示词用于平台外的 AI 助手，不是平台内业务智能体的系统提示词。网页版 AI 不会仅凭仓库地址就获得本机操作权限；本机安装需要 Docker，团队已有服务时运营人员只需浏览器。在线提示词可能晚于已发布 ZIP，旧包的操作仍以对应版本手册为准。

## A. 第一次接手

```text
请接手这个开源电商数据中台。
我给你的是：[离线运行包/完整公开源码/网页访问]，位置：[路径或地址]。
先确认材料类型与实际版本，再读现有 docs/AI_DIY_GUIDE.md、
根目录 LICENSE、THIRD_PARTY_NOTICES 和本次任务相关文档。
只有拿到完整源码时才读取根 AGENTS.md 与 docs/README.md；
文件不存在就说明缺失，不假定离线包能重建整个程序。
本次目标：[具体业务问题]。本次允许修改的范围：[范围]。
保留已有数据与配置，不输出秘密或真实业务文件；源码分发遵守 GPL 和第三方许可。
先做不依赖缺失业务口径的工作；只有缺失信息会改变结果时再问。
```

## B. 普通表建模块，不先改代码

```text
请根据脱敏样表 [路径] 判断能否用页面新建模块。
业务目标：[目标]；日期粒度：[日/订单/其他]；有效状态：[状态]；
指标与单位：[内容]；人工核对答案：[至少3组]。
请给出字段映射、计入状态、重复批次处理和第一批验收点，
再用第二批样表 [路径] 验证规则复用。
页面能力足够就不改代码；不足时说清缺的是哪一种能力。
不能把退款口径、库存聚合或费用分摊规则猜出来。
```

## C. 完整源码的复杂 DIY

```text
我已提供完整公开源码。请实现：[模块/规则/页面需求]。
脱敏样表：[路径]；字段字典：[内容]；关联键：[内容]；
公式与舍入：[内容]；人工答案：[内容]；失败处理：[内容]。
先阅读当前实现和测试，选择最小足够的改造；保留来源追溯与回滚。
测试覆盖与本次改动相关的正常、缺列、重复键、零分母、
状态过滤、重复执行和失败回滚；只在隔离测试库中执行。
交付变更文件、测试结果和人类验收步骤。
本次不包含推送、发布或升级正式实例，除非我另有明确要求。
```

## D. 排查使用问题

```text
版本：[版本]；运行方式：[本机Docker/虚拟机/公司网页]；
问题发生时间：[时间]；操作：[步骤]；错误文字：[脱敏内容]；
预期：[内容]；实际：[内容]。
先只读诊断，检查服务健康、目标实例与相关错误，不输出秘密。
不要用删除数据卷、清空数据库或重装来代替定位原因。
区分已证实原因与假设，并给出最小修复建议；本次尚未授权写入修复。
```

## E. 已明确授权的版本升级

```text
请把指定实例 [名称与地址] 升级到 [已验收版本与公开 Release 标签]。
允许在备份后短暂停止并重建该实例的必要应用服务，保留真实数据。
先确认项目名、卷、端口、原镜像和自定义配置；保留原密钥，
检查迁移与启动seed对已有智能体提示词的影响。
备份放到 [受控目录]，不进入分享包。使用既有备份与验证工具。
升级后验证镜像版本、健康、登录、主要页面、模块/图表与数据数量。
不执行数据卷删除；如失败需覆盖数据库恢复，先说明影响再请求该项授权。
```

## F. 交付检查

```text
请复核候选公开交付包 [路径]；在完整检查通过前不要上传 Release。
确认人类使用说明、AI接手说明和提示词分开且真实包含在ZIP内，
检查链接是否指向包内存在的文件；明确普通用户不需要源码开发工具。
检查真实数据、秘密、数据库备份和本机路径是否误入分享内容。
使用已有版本清单和校验机制核对整套资产，不新增无事故依据的门禁。
最后列出已验证、未验证和接收方首次使用还需完成的事项。
```
