# 给人看的使用手册

适用对象：第一次从公开仓库或正式 Release 获取程序的使用者、业务负责人和管理员。不需要先学编程。本文讲安装和使用；给开发 AI 的材料单独放在 [AI_DIY_GUIDE.md](AI_DIY_GUIDE.md)，可复制提示词放在 [AI_PROMPTS.md](AI_PROMPTS.md)。

## 1. 这是什么，装好后会看到什么

这是一套轻量电商数据中台：把 Excel/CSV 按业务模块整理，重复使用已确认的字段和统计规则，再查看明细、对比、图表及可选的 AI 分析。它不会自动登录电商后台取数，也不代替财务账本。

全新安装包含程序、内置入口和预置配置，但没有分享者的真实经营数据、历史图表和数据库里的自建模块。界面能打开但部分页面为空是正常现象，不是安装失败。配套工作台方案和合成样例需要另行导入；示例不能作为真实经营结论。

同一实例的数据由可信团队共享，不是按公司隔离的多租户系统。不要让互不信任的客户共用一套实例。

## 2. 先选路径，再解压

| 你的情况 | 应做什么 |
|---|---|
| 管理员已经给了网页地址 | 浏览器打开地址、用分配的账号登录；自己不用装 Docker |
| 在自己电脑从零安装 | 使用平台离线包并安装 Docker Desktop |
| 电脑已经有这套中台 | 按升级处理；不要双击另一份包试运行 |
| 在 Linux 虚拟机中运行 | 在虚拟机内安装 Docker Engine 与 Compose；先按下面网络说明访问 |
| 买服务器给团队使用 | 交给管理员使用同版本云工具包；不是把本机端口直接暴露公网 |
| 要让 AI 改底层代码 | 先看 AI 接手说明；离线包不等于完整源码仓库 |

“GitHub”存放版本，“Docker”运行程序，“服务器/电脑/虚拟机”提供机器。下载 GitHub 源码并不能替代 Docker 或服务器。本项目当前没有不依赖 Docker 的普通用户桌面安装器。

## 3. 收到哪些文件

正式发布的成套 Release 包含以下七项资产，必须来自同一个版本；若下载页面还没有对应标签或附件，就不要用旧私有包冒充公开版：

| 文件 | 用途 |
|---|---|
| `ec-data-platform-YYYYMMDD.zip` | 平台离线运行包，含镜像、启动器和本手册 |
| `ecommerce-workbench-v1.zip` | 电商方案和 7 份合成样例，按其中 README 导入 |
| `ec-cloud-kit.zip` | 给服务器管理员的部署工具 |
| `release-manifest.json` | 平台文件与源码版本清单 |
| `image-provenance.json` | 镜像来源和版本记录 |
| `cloud-kit-manifest.json` | 云工具版本记录 |
| `SHA256SUMS.txt` | 以上六项文件的传输校验值 |

只想本机使用时主要操作平台 ZIP；其他资料仍建议一起保留。不需要打开、修改镜像 TAR 或清单 JSON。GitHub 自动生成的 “Source code (zip)” 不是安装包。

Windows 可用 `Get-FileHash .\ec-data-platform-YYYYMMDD.zip -Algorithm SHA256` 与可信来源的 `SHA256SUMS.txt` 对照；命令不可用时请维护者协助。校验不一致不要安装。不要把自己填过数据的模板、备份或 `.env` 追加进分享包。

## 4. Docker 与机器准备

### Windows

从 [Docker 官方 Windows 安装说明](https://docs.docker.com/desktop/setup/install/windows-install/) 安装，按当前官方要求配置 WSL 2/硬件虚拟化。公司受管电脑请 IT 协助，不要擅自关闭安全软件或修改公司策略。Docker Desktop 的许可适用性由管理员按组织情况核实。

启动 Docker Desktop，在终端运行 `docker info` 和 `docker compose version`。前者必须能访问服务端；只有 `docker --version` 有输出不能证明 Docker 已运行。本包使用 Linux 容器，不使用 Windows 容器模式。

镜像、数据库和备份都占磁盘空间；安装前查看系统盘及 Docker 数据盘空间。数据增长后及时做受控备份，不要通过删除 Docker 数据目录来腾空间。

Docker 29/containerd 的镜像标识与经典存储不同。使用包含该兼容修复的版本；若旧启动器报告镜像 ID 不符，不要删除校验或改清单中的值，向维护者索取修正版。

### Mac 与芯片架构

按 [Docker 官方 Mac 安装说明](https://docs.docker.com/desktop/setup/install/mac-install/) 选择对应芯片版本。当前 Release 构建的是 Linux amd64 应用镜像；Apple Silicon/其他 ARM 环境不能宣称已验收，可能依赖模拟且性能不同。先让维护者确认架构兼容，不要把脚本支持 macOS 理解为所有 Mac 都已验证。

### 需要自己装虚拟机吗

普通 Windows 用户不必为了本包再装 VMware/VirtualBox。Docker Desktop 会管理自己的运行环境。若 Windows 本身已运行在虚拟机中，Docker Desktop 还需要底层支持嵌套虚拟化，见 [Docker 官方虚拟机说明](https://docs.docker.com/desktop/setup/vm-vdi/)；不支持时换受支持的机器，不要反复重装本包。

使用 Linux 虚拟机时，`localhost` 指虚拟机自己，不是宿主电脑。默认端口只监听虚拟机的回环地址，可在虚拟机内打开浏览器；或者由管理员建立 SSH 本地转发（将占位的用户名/IP 换成实际值）：

```bash
ssh -L 3997:127.0.0.1:3997 USER@VM_IP
```

保持 SSH 会话，再从宿主浏览器打开 `http://localhost:3997`。NAT/桥接、SSH 连通性由管理员配置；不要为方便而把数据库端口改成对外开放。虚拟机快照不替代数据库与原始文件备份。

## 5. 第一次安装：仅限空环境

1. 将平台 ZIP 完整解压到固定目录，例如 `D:\ec-platform`。不要在压缩预览窗口启动。
2. 确认电脑没有另一个同名中台实例。仅换目录或修改 `INSTANCE_ID` 不能隔离实例；容器名、Compose 项目、端口和卷都要独立，交给管理员处理。
3. 在 `deploy` 内复制 `.env.example` 为 `.env`。Windows 打开“文件扩展名”，避免实际保存成 `.env.txt`。
4. 使用文本编辑器替换所有 `change_me`。实例标识和密码规则见下表，不要把填写后的文件发给 AI 或群聊。
5. Windows 双击 `start.bat`；macOS/Linux 在解压根目录运行 `bash start.sh`。
6. 等待启动器提示健康，浏览器打开 `http://localhost:3997`。冷启动、导入镜像需要时间，不要连续重复点击。
7. 空库使用 `admin` 和你设置的管理员密码登录。若复用了已有数据库，仍需使用库中原密码；修改 `.env` 不会重置已有账号。

| 配置项 | 人类需要知道的事 |
|---|---|
| `INSTANCE_ID` | 稳定实例标识，3～63 位小写字母/数字/下划线/连字符，不能保留占位值 |
| `POSTGRES_PASSWORD`、`APP_DB_PASSWORD` | 两个不同的数据库密码，使用密码管理器生成；仅字母、数字、点、下划线、波浪号、连字符 |
| `ADMIN_PASSWORD` | 首次创建 admin 的密码；不是持续生效的密码重置按钮 |
| `JWT_SECRET` | 独立长随机登录密钥，不能与其他密码相同；已有实例不随意改 |
| `ENCRYPTION_KEY` | 已有实例保持原值；为空时旧密文可能依赖 JWT，不能随意补值或轮换 |
| `DEEPSEEK_API_KEY` | 可暂留空；普通数据功能可用，AI 不可用 |

密码配置使用严格的 `NAME=VALUE` 单行格式，不加引号、空白、反斜杠、`$` 插值或行尾注释。由启动器校验实际规则；不要为通过启动而削弱校验。

“离线包”表示运行镜像已带齐，不代表 AI 能离线使用；模型调用及首次安装 Docker 仍可能需要网络。

## 6. 每个页面干什么

| 页面 | 主要用途 |
|---|---|
| 数据 | 上传 Excel/CSV、查看原始行、归入模块；管理员另有受限外部 SQL 查询 |
| 模块管理 | 每类业务一个工作台，查看处理结果、对比及模块配置 |
| 分析中心 | 汇总经营指标、数据记录和待处理提醒，再进入对应业务 |
| 看板/经营驾驶舱 | 查看已创建的趋势和对比图；页面名称以当前版本为准 |
| 智能体 | 配置模型后使用分析、文案等任务；不是底层代码编辑器 |
| 方案交付 | 管理员导入/校验授权方案；不会自动复制对方业务数据库 |
| 设置 | 管理账号和服务配置；不要把密钥截图分享 |

## 7. 第一次跑通自己的数据

1. 先保留原始文件，只用脱敏小样试跑。确认日期范围、哪些状态算有效、指标单位，以及人工正确答案。
2. 上传文件，已识别的进入已有模块；未识别的由你确认归属或创建新模块。
3. 创建模块时确认日期、金额、数量、商品、店铺、状态等对应列，并选择计入统计的状态。未计入不等于原始行已删除。
4. 核对上传行数、有效行数、未计入原因及关键合计，再看图表。
5. 上传第二批不重叠的同类小样，验证规则能复用。确认后再导入正式数据。

普通 Excel/CSV 入口有文件及行数限制，以当前页面为准；管理员大 CSV 入口是另一条受限路径，不能靠改后缀绕过限制。一个模块只放业务含义和结构兼容的文件。

文件名保留已确认的共同关键词，并附日期/批次。不要把同一数据改名再上传，否则可能重复统计。同名覆盖、删除文件、清理历史由管理员确认。上传成功不代表公式和经营口径正确。

普通单表 DIY 详见 [自助模块说明](SELF_SERVICE_MODULES.md)；复杂 JOIN、特殊公式、新接口再交给开发 AI，不要强行把不相关字段映射到一起。

## 8. 方案和模板怎么用

- 电商工作台：解压配套 ZIP，先读其中 README，再在“方案交付”导入 `.solution.json`，最后上传 `samples` 中合成文件验证。合成样例日期为 2099 年；正式使用前由管理员移除或取消分配样例来源，避免混算。
- 前台利润：平台包 `templates/front-profit` 内的 `01` 是标准结果上传表，删除/覆盖黄色示例行后填写；`02` 是管理员数据准备与映射工具，不是整本直接上传的业务事实。细节见模板目录 README。
- 前台利润自动归集仍有真实样本与生产验收边界，不要把合成演示当作已核验的财务结果。

## 9. 两种 AI 不要混淆

平台内业务 AI：读你允许使用的数据做分析/文案，需模型 Key，可能将采样数据发送到外部模型。公司不允许外发就不要启用。

平台外开发 AI：例如接手文件和代码的开发助手，负责规则设计或改造。给它的是脱敏样表、字段字典、人工答案和 AI 专用说明，不是整份真实数据库或密码。

## 10. 停止、备份、升级

短期不用：在解压目录的 `deploy` 中运行 `docker compose stop`；再次运行原目录启动器。不要执行 `docker compose down -v`，不要删除数据卷。

程序 ZIP 不是数据库备份。保留原始文件归档，并由管理员在程序目录之外建立受控备份目录，例如 `D:\private-ec-backups`。从解压根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\backup.ps1 -OutputRoot "D:\private-ec-backups"
```

该目录需先创建；脚本成功后保留 dump 和清单。备份包含真实数据和敏感信息，不能转发。`.env` 不在此数据库备份中，管理员要独立安全保管原密钥。恢复会覆盖目标数据库，普通用户不要自行尝试；完整步骤见 [离线包使用说明](离线包使用说明.md)。

升级必须先暂停录入、备份、记下版本/卷/模块与数据数量，保留旧镜像和原 `.env`，核对新版本迁移，再重建目标应用服务。不能把新目录空启动当成升级，也不能让两个应用同时写同一数据卷。只回退镜像不一定能回退数据库；涉及数据恢复必须再次明确目标和覆盖范围。

## 11. 常见问题

| 现象 | 先查什么 |
|---|---|
| Docker 命令存在但启动失败 | Docker Desktop 是否运行、Linux 容器/虚拟化是否满足要求 |
| 3997 打不开 | 启动器最后的错误、容器健康、端口是否被旧实例占用 |
| 虚拟机内可打开，宿主不行 | `localhost` 指向不同机器，按 SSH 转发说明处理 |
| 登录失败 | 是否空库；已有库的密码不会被 `.env` 重置 |
| 能登录但没有演示数据 | 新安装为空业务数据；按方案说明导入合成样例 |
| 行数或金额不对 | 重复批次、状态筛选、日期范围、字段映射、公式口径 |
| AI 不可用 | Key、模型服务网络/额度和数据外发授权 |
| 升级后像换了新系统 | 可能使用了新项目或新卷；停止录入，找管理员，不要删旧卷 |

求助时只提供版本、运行方式、出错时间、步骤、错误文字和脱敏截图。不要发送 `.env`、Token、连接串或真实报表。
