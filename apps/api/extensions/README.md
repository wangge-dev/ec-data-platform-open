# DIY 扩展起步卡

这套目录会随离线分享包一起交付，只包含配置范例，不包含账号、密钥和业务数据。

## 先判断是否适合 DIY

| 需求 | 业务人员页面完成 | 配置范例完成 | 需要开发 |
|---|---|---|---|
| 单表字段映射、状态筛选 | 是 | 是 | 否 |
| 两个数值字段相加、相减、相乘、相除 | 是；在“新建模块 → 字段对应 → 安全计算字段”设置 | 是 | 否 |
| 单一字典表补品牌、店铺等属性 | 暂不开放页面自由配置 | 是；参考 `modules/example-sales-enriched.module.json` | 首次应由懂数据的人复核关联键 |
| 两三行合并表头 | 是；在上传页选择表头层数 | 不需要 | 否 |
| 一对多 JOIN、多事实表 JOIN、按时间生效的 JOIN | 否 | 否 | 是 |
| 任意 SQL 公式、窗口函数、跨行计算 | 否 | 否 | 是 |
| 正则清洗、拆列、模糊匹配、业务例外规则 | 否 | 否 | 是 |

## 接收方开始前只需填这张卡

复制下面内容，为每一类业务文件填写一次：

```text
业务名称：
一行代表什么（数据粒度）：
唯一键或可能重复的原因：
日期字段：
金额/数量字段及单位：
计入统计的状态：
需要补充的字典字段：
事实表关联键：
字典表关联键（必须唯一）：
计算字段：字段名 = 左字段 运算 右字段：
特殊空值示例：
需要删除、替换、拆分或合并的异常值示例：
预期总行数与金额合计：
```

不知道“数据粒度、唯一键、关联键”的文件，不要直接配置 JOIN 或公式；先让提供数据的人把三项说清楚。

## 推荐顺序

1. 先保留一份原文件，不在原件上修改。
2. 上传页完成工作表拆分、2/3 行表头合并、宽表转长表或大 CSV 流式导入。
3. 预览行数、列名、空行警告和异常值。
4. 新建普通模块，映射日期、金额、数量、店铺等字段。
5. 在页面增加安全计算字段；比例会按“分子合计 ÷ 分母合计”计算，不平均行级比例。
6. 只有单一、唯一键字典补字段时，才复制关联范例并修改 JSON。
7. 运行 `pnpm diy:validate <文件>`；验证通过后再安装、分配数据和跑 ETL。
8. 用源文件总行数、金额合计和抽样记录做验收，再交付看板。

## 三个范例

- `modules/example-sales.module.json`：最小普通销售模块。
- `modules/example-sales-enriched.module.json`：商品字典关联 + 毛利计算字段。
- `solutions/ecommerce-starter.solution.json`：多个模块组成的无数据方案包。

## 关联的硬边界

- 配置校验会拒绝不存在的 JOIN 左侧字段、不安全的输出字段、重复写入同一输出字段和任意 transform。
- 配置验证不能证明字典键在真实数据中唯一。首次运行前必须检查；一对多关联不能当普通字典 JOIN 使用。
- 特殊清洗必须提供“原值 → 目标值”样例和验收合计。没有例外样例时，不让系统猜。
- 自由关系图、跨源任意 JOIN 和任意表达式执行器不属于分享版范围。
