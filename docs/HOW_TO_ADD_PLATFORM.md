# 调整内置模块的平台识别（开发人员）

普通用户遇到新业务文件时，应优先使用页面上的「新建模块」向导：
[SELF_SERVICE_MODULES.md](./SELF_SERVICE_MODULES.md)。

本文只适用于“新文件仍属于现有内置复杂模块，并且要复用该模块的受控
JOIN/转换逻辑”的开发场景，例如给内置销售订单增加一种平台导出格式。

## 心智模型（一句话）

**平台 = 板块模块 JSON 里的 `platforms[]` 一项。**

```
板块（module）          平台（platform）
─────────────          ──────────────
orders 销售订单    ─┬─→  淘工厂 / 进口超市 / 旗舰店 / 阿里健康 / 京东
ads 广告          ─┬─→  京东广告 / 抖音广告 / ...
inventory 库存    ─┬─→  A仓 / B仓 / ...
```

- 加平台 = 编辑某个板块的 `modules/<板块>.json`，在 `platforms[]` 加一项。
- 加完调 `POST /api/modules/reload` 热生效，**不改代码、不碰数据库、不重启容器**。

## 前置：先认清单

1. 你要加的平台属于哪个板块？销售订单→`orders.json`，广告→`ads.json`，库存→`inventory.json`，成本→`cost.json`。
2. 拿到该平台导出的原始 Excel，看表头列名（这是 `columnOverrides` 要填的值）。
3. 看文件名规律（这是 `filePattern` 要匹配的正则）。

## 三步加平台

### 第 1 步：复制最像的现有平台

打开 `apps/api/src/modules/<板块>.json`，找到 `platforms[]`，复制一项改成新平台。以 `orders.json` 为例：

```json
{
  "code": "jd",                      // 平台代号，英文小写下划线
  "name": "京东",                     // 平台中文名（显示用）
  "filePattern": "订单列表",           // 匹配导出文件名的正则（见下文）
  "patternFlags": "i",                // i=忽略大小写，""=精确
  "enabled": true,
  "columnOverrides": {
    "product_id": "商品ID",
    "qty": "购买数量",
    "amount": "实付金额",
    "pay_time": ["付款时间", "下单时间"],
    "main_order_no": "主订单号",
    "row_key": "子订单号"
  }
}
```

### 第 2 步：填 columnOverrides（关键）

**左边是规范列名**（板块的 `columns[]` 里定义的 `name`，不能改），**右边是该平台 Excel 表头里的真实列名**（一定要和导出文件的表头一字不差）。

- 打开原始 Excel，把表头列名逐个对应过来。
- **填原始表头列名（raw），不是规范化后的**。例如原表头 `Order ID`，要填 `"Order ID"`（含空格），不是规范化后的 `Order_ID`。中文列名无空格时 raw 和规范化名通常相同；英文列名带空格或标点时必须用 raw。
- 如果一个规范列在不同导出里叫法不一，用数组给候选：`"pay_time": ["付款时间", "下单时间"]`，引擎按顺序取第一个非空的。
- 模块 `columns[]` 中所有 `required:true` 的字段都必须能从原始表头解析；例如当前 `orders` 的 `product_id`、`amount`、`row_key` 都是必填。只有未标记 `required:true` 的维度列才可缺省。

### 第 3 步：热重载

```bash
# 改完 JSON 调这个接口，立即生效（不用重启 docker）
curl -X POST http://localhost:4000/api/modules/reload \
  -H "Authorization: Bearer <你的token>"
```

返回 `{"ok":true,"reloaded":<当前加载数量>,"modules":[...]}` 就成了；模块数量会随内置配置和数据库用户模块变化，不要固定判断某个数字。

## 怎么验证加对了

1. **文件归属**：传一个该平台的 Excel 到数据页。文件列表里它的徽章应显示 `销售订单 / 京东`（绿色，可点），**不再是红色的「未匹配」**。
2. **ETL 跑通**：上传后自动跑 ETL，提示「已识别为 京东，写入 N 行」。
3. **汇总表**：分析中心/看板选「销售订单」模块，能看到京东的销售额。

如果徽章还是「未匹配」，是 `filePattern` 没匹配上文件名——改 filePattern 再 reload。

## filePattern 怎么写

它是一个保守的文件名匹配模式，匹配**导出文件的原始文件名**。为避免恶意或误写正则拖垮扫描，仅支持：普通文字、顶层 `|`、开头/结尾锚点 `^`/`$`、每个分支最多一个 `.*`、每个分支最多一个文字后的 `?`，以及转义后的正则标点。常见写法：

| 平台导出文件名 | filePattern | 说明 |
|---|---|---|
| `GEI@EXPORT_ORDER_INFO@260621...xlsx` | `GEI@EXPORT_ORDER_INFO` | 淘工厂订单 |
| `ExportOrderList2662...xlsx` | `ExportOrderList` | 旗舰店订单 |
| `orders.export.20260623.xlsx` | `orders\.export` | 英文订单导出文件（`.` 要转义） |
| `京东订单_202606.xlsx` | `京东.*订单` 或 `京东` | 京东订单 |

- 写**这个平台导出文件名里稳定出现的片段**，不要写日期/序号那种会变的。
- `.` 在正则里是任意字符，要匹配字面点号写 `\.`。
- 不要写括号、字符类、`+`、`{}`、回溯引用或前后查找；复杂模式会被配置校验直接拒绝。
- `patternFlags` 只允许 `i`（忽略大小写）和 `u`，不允许会保存匹配状态的 `g`/`y`。
- 多个平台别用会互相匹配的 filePattern（比如 `order` 太宽会匹配到所有含 order 的文件）。

## 常见坑

1. **列名对不上**：columnOverrides 右边必须和 Excel 表头**完全一致**（含空格、标点）。从 Excel 复制表头最稳。注意填 raw 原始表头（见第 2 步）。
2. **加了平台但文件还是未匹配**：99% 是 filePattern 没匹配上。在文件列表看文件名，对照正则。
3. **忘了 reload**：改完 JSON 不调 `/reload`，配置没生效（容器还用着内存里的旧配置）。reload 会重读 modules 目录的文件——开发期 modules 目录挂载进容器，宿主改完 JSON 调 reload 即时生效，不用重启或重建镜像。
4. **dictKey**：订单板块靠 `join.on.product_id` 的值决定字典侧用哪列关联（一般是 `"id"`）。改这个前先理解字典结构，通常不用动。
5. **字典/维护表不是平台**：维护表（品牌字典等）是字典模块，上传时按文件名自动识别成 `role=brand_dict`，**不进 platforms[]**。别把维护表当平台加。
6. **报表带元信息行**：部分广告或经营报表前几行是标题/店铺名/统计周期等键值对，真表头在后面。导入时会**自动跳过元信息行**（找第一个「≥3 列非空且下一行也 ≥3 列」的行当表头），不用手动处理。
7. **维度列不必填**：shop_id/shop_name 这类维度列不是必填。如果某平台报表整文件单店铺、数据行没有店铺列，留空即可，行照常入库（店铺相关分组/JOIN 不可用，但金额/花费等指标正常）。

## 加全新业务模块（不是内置平台）

如果是不存在的业务（比如「流量」「客服」），正常方式是使用 UI：

1. 在数据页上传文件并勾选；
2. 点击「创建模块」，或到模块管理页点击「新建模块」；
3. 逐项映射日期、金额、数量、商品和状态；
4. 点击「保存并处理」。

系统会把用户模块持久化到数据库并立即执行，不需要复制 JSON、调用
reload 或重启容器。只有需要 JOIN 字典、复杂去重或自定义计算的内置模块，
才使用 `hasTransform:true` 和 transform 钩子。
