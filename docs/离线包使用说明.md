# 离线包使用说明

新手先读 [给人看的使用手册](USER_GUIDE.md)；交给开发 AI 时另用 [AI 接手与 DIY 说明](AI_DIY_GUIDE.md) 和 [提示词](AI_PROMPTS.md)。本文保留管理员所需的启动、备份和恢复细节。

## 开源与数据范围

本包包含可读模块／运行代码，项目自有部分依 [GPL-3.0-only](../LICENSE) 分发；第三方组件许可证及其要求继续适用，见[第三方说明](../THIRD_PARTY_NOTICES.md)。对应版本的完整公开源码可从同一 Release 标签取得。公开包不包含用户的经营数据库、备份、密码或 API Key；切勿把填入真实数据后的运行目录重新上传。

离线启动脚本每次都会载入包内 `ec-data-images.tar`，并用打包阶段已与 `release-manifest.json` 交叉审计的 `release-image-ids.txt` 核对镜像和实际容器的镜像 ID；五个服务均声明 `pull_policy: never`，不会因 `latest` 标签联网拉取。本机已有同名旧镜像不会被静默复用。默认宿主端口只监听 `127.0.0.1`。若本次重建后的镜像或健康检查失败，启动器会停止本次 Compose 服务（不删除容器和数据卷），避免错误版本继续对外服务。

本说明面向收到 `ec-data-platform-YYYYMMDD.zip` 的使用者。离线包已包含四个 Docker 镜像，不需要 Node.js、pnpm 或源代码。

离线包还包含 `templates/front-profit/` 前台利润正式模板包。模板经过脱敏，只保留字段、公式、映射结构和明确标记的类型识别示例，不含真实店铺、运营、SKU、订单或经营金额。

`apps/api/extensions/` 包含可移植的模块、连接器和 `vertical-solution/v1` 示例清单，并以只读方式挂载到 API 容器。该目录是配置资产，不包含连接密码或业务数据；不要把填有客户密钥、真实数据或可执行脚本的文件放入其中。

登录后，管理员可从侧栏进入“方案交付”：在来源实例选择普通用户模块并下载 `.solution.json`，再到目标实例完成校验和原子应用。空实例会执行首次安装；同一方案的更高版本可在模块集合和语义合同不变时原子升级，并可立即整组回滚。非本方案同名模块、客户本地定制、并发变化、缺少连接器或连接器版本不一致时都会停止，不会静默覆盖现场配置。升级若改变导入映射或新增字段，请随后重新运行相关模块 ETL。

## 启动

1. 安装并启动 Docker Desktop。
2. 解压 ZIP 到任意目录。
3. 复制 `deploy/.env.example` 为 `deploy/.env`。
4. 替换所有 `change_me` 示例值。`INSTANCE_ID` 是这套实例稳定且唯一的运维标识，只能使用 3～63 位小写字母、数字、下划线或连字符；上线后不要随意改名。`ADMIN_PASSWORD`、`JWT_SECRET` 和两个数据库密码必须使用不同的强值。四项密钥都按严格 `NAME=VALUE` 单行填写，只使用不带引号的 ASCII 值，不要加行尾注释，也不要使用 `$` 插值、空白、引号或反斜杠。两个数据库密码会进入 PostgreSQL URI，只能使用字母、数字、点、下划线、波浪号和连字符。
5. Windows 双击 `start.bat`；macOS/Linux 运行 `bash start.sh`。
6. 等待提示健康后打开 <http://localhost:3997>。空数据库首次启动时，使用 `admin` 和你设置的 `ADMIN_PASSWORD` 登录；若复用或恢复了已有数据库，应使用库中现有管理员密码。

`DEEPSEEK_API_KEY` 可以暂时留空，此时上传、ETL、模块和普通看板可用，AI 功能不可用。

`ADMIN_PASSWORD` 只在数据库尚无 `admin` 时创建该账号，不是长期密码重置开关。修改 `.env`、重启启动器或恢复数据库都不会覆盖已有管理员密码；需要重置时由获授权管理员在用户管理中完成。

## 使用前台利润模板

1. 打开 `templates/front-profit/README-前台利润模板使用说明.md`。
2. 普通用户只需要复制 `01-电商前台利润单表上传模板.xlsx`，删除或覆盖第 2 行黄色示例行，再粘贴自己的标准利润数据。
3. 空白数据中台首次使用时，在“数据 → Excel 上传”中上传该文件，并按说明创建“电商前台利润”模块。
4. 后续保持文件名共同关键词不变，即可自动归入同一模块。
5. 管理员需要从经营明细、费用和映射重新整理标准结果时，再使用 `02-电商前台利润数据准备与映射模板.xlsx`。

普通用户可以上传新的经营文件；若文件名与已有文件完全相同，请改用新的批次文件名，或由管理员确认后执行同名覆盖。维护表、品牌字典、成本字典、店铺 PIC 字典等全局映射材料只能由管理员上传，文件删除和数据源配置也只对管理员开放。

传输后可用 `templates/front-profit/SHA256SUMS.txt` 复核模板完整性。请勿把自己填入真实数据后的副本重新打进离线包或提交到 Git。

## 包内不包含什么

- 不包含打包者的账号密码、API Key 和 `.env`。
- 不包含真实业务 Excel/CSV、数据库和当前实例数据库内的用户模块；包内仅包含经过审核的纯配置扩展示例，以及经过哈希锁定的脱敏前台利润模板。
- 不包含完整源代码和 Git 历史，不能用作继续开发的源码包。

如需升级或继续开发，请向维护者索取新的离线包或开发换机包，不要在离线包内执行 `docker compose up --build`。

## 实例备份

先在离线包之外准备一个受控目录。不要把备份写进解压目录、源码仓库、Git、离线发布包或普通共享盘。

Windows PowerShell：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\backup.ps1 -OutputRoot "D:\encrypted-backups"
```

macOS/Linux：

```bash
bash backup.sh --output-root /secure/encrypted-backups
```

脚本使用 PostgreSQL 一致性快照生成自定义格式转储，先在容器内执行 `pg_restore --list` 校验，再复制到宿主机并计算 SHA-256。成功后只产生一个 `ec-data-instance-backup-<INSTANCE_ID>-<UTC时间>/` 目录，里面恰好包含：

- `ec_data.dump`：数据库转储；
- `backup-manifest.txt`：实例 ID、来源代码修订、敏感性声明、字节数和 SHA-256。

备份包含账号密码哈希、业务数据以及可能存在的加密连接凭据，按敏感资产处理；建议在静态加密磁盘或加密对象存储中保存。备份明确不含 `deploy/.env`，也不含 Redis 临时状态。源码树直接执行备份脚本时，工作树必须干净，否则脚本拒绝把某个提交号写入备份清单；离线运行包则使用发布清单中的源码修订。生产运维仍需在外部补上定时调度、保留与删除策略、异机副本、失败告警和定期恢复演练；本包脚本只提供一次性、可审计的备份原语。

## 实例恢复

恢复会完整替换目标 `ec_data` 数据库并清空 Redis 临时状态。脚本在任何停服务或数据变更前，先检查备份目录白名单、清单合同、字节数、SHA-256、PostgreSQL 归档可读性、目标实例 ID 和来源代码修订。确认无误后停止 API/迁移服务，重建数据库、恢复数据、运行前向迁移并等待所有服务健康；中途失败会再次停止 API 和迁移服务，不会让部分恢复的数据继续对外提供服务。

Windows PowerShell：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restore.ps1 `
  -BackupPath "D:\encrypted-backups\ec-data-instance-backup-customer_a-20260818T020000Z" `
  -ConfirmInstanceId customer_a `
  -AcknowledgeDataOverwrite
```

macOS/Linux：

```bash
bash restore.sh \
  --backup-path /secure/encrypted-backups/ec-data-instance-backup-customer_a-20260818T020000Z \
  --confirm-instance-id customer_a \
  --acknowledge-data-overwrite
```

只有确认目标版本能读取该备份时，才可对不同或无法证明相同的代码修订额外传入 PowerShell 的 `-AcknowledgeReleaseMismatch`，或 Bash 的 `--acknowledge-release-mismatch`。这只是显式风险确认，不是自动兼容性证明；禁止用旧应用恢复来自未来版本数据库的备份。

恢复不会覆盖目标 `deploy/.env`。若数据库中的外部连接密码需要继续解密，目标必须从独立秘密管理中取得来源实例原有的 `ENCRYPTION_KEY`；如果来源未显式设置该值而是由 `JWT_SECRET` 派生，则也必须保持原 `JWT_SECRET`，否则应在恢复后重新录入连接凭据。管理员登录密码来自恢复后的数据库，不会被目标 `.env` 中的 `ADMIN_PASSWORD` 重置。

## 停止与保留数据

在 `deploy/` 目录执行：

```powershell
docker compose stop
```

再次运行 `start.bat` 会使用原数据卷继续启动。不要执行 `docker compose down -v`，除非确认要永久删除这套实例的数据。
