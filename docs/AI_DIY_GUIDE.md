# 给 AI 的接手与 DIY 说明

适用对象：经用户授权的开发助手。人类安装使用请读 [USER_GUIDE.md](USER_GUIDE.md)；可复制任务模板见 [AI_PROMPTS.md](AI_PROMPTS.md)。本文件随离线包交付，不假定收件人拥有完整源码。

## 1. 先判断拿到什么，不要猜路径

| 手中材料 | 可以做什么 | 不应承诺什么 |
|---|---|---|
| 只有网页账号 | 指导页面自助模块、解释结果 | 不能直接改服务器代码 |
| 离线运行包 | 阅读包内配置、模块说明、已有运行代码，设计受支持 DIY | 不假定存在 package.json、完整测试、Git 或可重建前端 |
| 完整公开源码仓库 | 依照仓库规则实现、测试和构建 | 未经明确要求不推送/发布/升级正式实例 |
| 数据库备份或真实文件 | 仅按明确授权用于指定私有环境 | 不作公开测试夹具，不混进分享包 |

离线包中优先读本文件、任务专项说明、根目录 LICENSE/THIRD_PARTY_NOTICES 和当前 `release-manifest.json`。完整仓库中再读根 `AGENTS.md`、`docs/README.md` 及相关源码。缺少源码或文件时明确说明缺失，不把不存在的路径当事实。

## 2. 产品事实

- 主链路：Excel/CSV 上传→归类/自助建模块→处理并保留来源→分析、对比和图表。
- 普通业务优先页面 DIY；复杂模块和平台适配需要受控实现。
- 管理员外部 SQL 是受限查询，不是自动同步或后台数据采集。
- 平台业务 AI 与外部开发 AI 分离；模型调用可能外发数据，先确认授权。
- 一套实例是可信团队共享的单租户边界，不是公开多租户 SaaS。
- 前台利润自动归集的合成测试不证明真实财务生产验收通过。

## 3. 人类必须提供的业务材料

至少取得：脱敏代表样表、列含义/单位、日期粒度、唯一键、有效状态、退款取消规则、公式及分母口径、3～5 组人工正确答案、第二批复用样例、数据规模与输出需求。材料不足先完成结构盘点，涉及金额口径不能猜。

保留来源文件和批次可追溯性。库存快照不能跨日期直接求和；比例通常要汇总分子分母后再相除，不能直接平均百分比。多表关联需证明键唯一性和关联失败如何处理。

## 4. 选择最低足够的改造层级

1. 同类新批次：复用现有模块，不改程序。
2. 稳定单表：页面自助创建；确认字段、状态、计算和第二批复用。
3. 已有成熟模块组合：使用授权方案包，先校验再应用，不覆盖未确认的本地定制。
4. 内置复杂模块的新报表格式：按 [HOW_TO_ADD_PLATFORM.md](HOW_TO_ADD_PLATFORM.md) 扩展适配，不重复造业务模块。
5. 多表关联、新接口或特殊公式：需要完整源码与隔离开发环境，按 [HOW_TO_ADD_MODULE.md](HOW_TO_ADD_MODULE.md) 实现并测试。

指标、图表与扩展能力以 [DIY_SEMANTIC_EXTENSIONS.md](DIY_SEMANTIC_EXTENSIONS.md) 为准；不能把任意代码放到纯 JSON 配置目录后声称它会自动执行。

## 5. 安全与授权

- 项目自有代码按 GPL-3.0-only 开源；衍生分发应遵守许可证并保留第三方许可信息。公开源码不包含也不授权公开任何人的真实业务数据、账号或备份。
- 不输出或上传 `.env`、密钥、密码、业务数据库和备份。用户明确授权运维时，可由受控工具使用既有秘密完成操作，输出只保留非敏感结果，不把秘密放进提示词或终端日志。
- 不更改正在使用的原始表；衍生结果另存，避免混入演示数据。
- 数据库写测试必须用显式独立 TEST_DATABASE_URL 或隔离 Compose；不回退正式 DATABASE_URL。
- 诊断不自动授权修复，改代码不自动授权升级正式库；本次已有明确授权的不重复索要。
- 不删除真实数据卷，不运行全局 prune，不为了测试通过移除已有安全控制。
- 不默认增设哈希、冻结合同或发布门禁。复用已有清单、校验和测试；只有具体事故风险且现有机制不足才提出新增。

## 6. 修改与验证

先检查当前版本、Git 状态、实际镜像、Compose 项目/配置路径/端口/数据卷；用户已有修改保留。只输出必要的元数据，不打印容器全部环境变量。

页面 DIY：用第一批核对字段、计入状态、行数和人工答案，再用第二批验证规则复用与重复导入行为。

源码改造：完成类型检查、相关单测、正常/缺列/空值/重复键/零分母/失败回滚等与改动相关的测试。仓库 API 测试通过 `pnpm test:api` 运行，保留串行设置；不要绕过既有参数导致共享临时目录冲突。项目固定 pnpm 9.15.9；若全局 pnpm 错位，使用 Corepack 调用并检查版本。

影响 Docker、迁移、备份或打包时执行对应隔离集成验证。不要在真实实例运行写测试。发布前运行既有依赖审计、`pnpm repo:check:public` 和本公开仓库的全历史密钥扫描，具体命令以当前仓库为准。已完成的必要验证不无理由反复全量运行。

## 7. 被明确授权升级时

1. 确认目标实例，记录原镜像 ID、绑定目录、卷和端口；区分“本地源码提交”和“正在运行的镜像”。
2. 暂停录入并使用现有备份脚本，私有保存数据库备份；独立保留原秘密配置，不能随包分享。
3. 比较迁移变化，检查启动 seed 是否覆盖已有智能体提示词或其他定制；不能仅凭“幂等”认定所有设置都会保留。
4. 使用已验收版本镜像；保留 Compose 项目、数据卷和原密钥，不把新目录空库启动当升级。
5. 按目标只重建必要服务；失败时停止错误应用，按兼容性决定是否退回原镜像。恢复备份会覆盖库，若需扩大为数据恢复必须明确说明并取得相应授权。
6. 验证健康、登录、页面、主要业务表行数、用户模块与图表；允许的变更逐项说明，不能仅检查 HTTP 200。

JWT/ENCRYPTION_KEY 不随升级随机轮换。旧密文可能依赖原 JWT；保留密钥或另行设计迁移。已有管理员密码不由 ADMIN_PASSWORD 环境变量重置。

## 8. 分享包复核与最终汇报

人类入口、AI 指南和提示词均应实际进入 ZIP，内部链接要能打开。提示词不得要求收件人读取包内不存在的 AGENTS/源码目录。

检查程序包与敏感备份分开、无真实业务文件与秘密；复用当前 manifest、provenance 与 SHA 校验版本一致性。将安装说明与源码开发命令分开，不让普通用户在离线包运行 `up --build`。

最终分开报告：已改内容、测试证据、未验证事项、本地是否升级、Release 是否发布、所用版本、回退资源位置。不要把“下载包一致”写成“现场数据与空白分享包完全相同”，也不要把“0 已知依赖漏洞”写成“绝对安全”。
