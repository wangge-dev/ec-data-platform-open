# 单实例分享版复杂能力 DIY 评估

## 执行摘要

复杂能力不应统一做成“自由配置”。适合业务人员 DIY 的是可枚举、可预览、可校验和可恢复的操作；复杂 JOIN、任意表达式和特殊清洗如果缺少数据粒度、唯一键和例外样例，开放按钮只会把开发难度转成数据事故风险。

本轮已把 2/3 行表头合并和四类安全计算字段放进现有页面；为单字典补字段增加了更严格的配置校验、可验证范例和接收方起步卡。自由关系图、一对多 JOIN、任意 SQL 和业务例外清洗继续关闭。

## 任务与分析范围

目标是降低接收方拿到单实例分享版后的上手成本。对象包括复杂 JOIN、多层表头、业务公式、自由数据建模和特殊清洗；不包含多租户、在线脚本执行器和完整通用 BI 建模器。

默认阅读者是熟悉 Excel、但不会写 SQL 的业务人员。对未知接收方的专属字段和口径不作推断。

## 数据与方法

证据来自当前源码中的表格导入、模块 Schema、默认转换、语义模型、模块向导、方案包和测试。使用能力分级矩阵判断“页面 DIY、配置 DIY、受控开发”三档，再以出错影响和可回滚性筛选前置动作。

本轮针对性证据包括 API 相关测试、Web 模块向导测试、前后端类型检查，以及 `example-sales-enriched.module.json` 的实际清单验证。测试只证明当前代码合同，不代表未知接收方数据天然符合合同。

## 关键发现

### 发现一：多层表头适合做成有上限的页面 DIY

- 事实：上传链路已有统一表头检测和宽转长边界，本轮增加显式 2/3 行表头合并。
- 证据：合并逻辑会横向补齐合并单元格、组合列名并记录处理摘要；对应测试覆盖标题行、空行和两层表头。
- 解释：层数是有限选择，结果列名可以预览和追溯，业务人员无需理解查询语言。
- 边界：更深层、多指标交叉表以及“合并表头 + 宽转长”组合仍有歧义，系统关闭失败。

### 发现二：常见业务公式适合用操作符向导 DIY

- 事实：底层已有计算列和表达式白名单，本轮在模块向导增加两个数值字段的相加、相减、相乘和相除。
- 证据：服务端只接受操作枚举和字段引用，再生成受限表达式；ratio 指标保存分子、分母字段，由语义层汇总后相除。
- 解释：把公式限制为结构化输入，既覆盖毛利、金额合计、单价乘数量和常见比率，又不需要开放 SQL。
- 边界：条件分支、窗口函数、跨行计算、常量参数和任意函数仍需配置范例或开发。

### 发现三：单字典补字段只能算半 DIY

- 事实：默认转换支持按字典 role 关联并补字段，模块清单可以纯 JSON 描述 JOIN。
- 证据：配置校验现会拒绝不存在的左字段、不安全的输出字段、空关联以及多个 JOIN 重复写同一字段；分享目录包含可验证范例。
- 解释：配置结构可以模板化，但“字典键是否唯一、关联后是否符合预期”只能用真实数据证明。
- 边界：一对多、按生效期、多事实表和模糊匹配 JOIN 不适合业务人员自行配置。

### 发现四：自由数据建模不适合当前分享对象

- 事实：系统以单模块语义合同和受控方案包为核心，没有关系图、模型依赖迁移和任意跨模块查询计划器。
- 证据：新图表必须引用版本化指标和维度；方案升级要求合同兼容并拒绝覆盖现场定制。
- 解释：这套约束保证可复制和可恢复，若直接增加自由模型画布，会同时引入循环依赖、口径漂移、性能预算和升级迁移问题。
- 边界：可以通过复制普通模块和行业方案实现“模板化建模”，不能宣传为自由建模。

### 发现五：特殊清洗必须从规则采集开始

- 事实：现有通用转换已处理空白、常见空值、千分位、货币符号、类型转换和必填门禁。
- 证据：接收方起步卡要求填写原值、目标值、异常样例、预期行数和金额合计。
- 解释：特殊清洗的难点不是执行替换，而是确认哪些值能改、是否影响财务口径以及如何验收。
- 边界：正则拆列、模糊匹配和业务例外没有样例时不自动猜测。

## 原因或机制分析

DIY 难度由四个因素决定：选择是否有限、执行结果是否可预览、错误是否能关闭失败、配置是否能版本化恢复。多层表头层数和四则操作满足这四项，因此可以进页面；单字典 JOIN 的配置可验证但数据唯一性不可静态证明，因此只适合模板化半 DIY；自由建模和特殊清洗会改变数据粒度或口径，必须保留人工复核。

## 结论

接收方现在可以较容易完成单表导入、2/3 行表头合并、字段映射、状态筛选和常见双字段公式。单字典补字段有可复制配置，但首次必须由懂数据的人确认关联键和验收合计。复杂 JOIN、自由建模和业务例外清洗不应继续向页面开放；为这些场景准备数据合同和样例，比增加一个“高级模式”更可靠。

## 风险与未知项

- 未知接收方的数据粒度、唯一键和财务口径可能使看似简单的公式或关联不成立。
- 2/3 行表头合并是显式工具，不会自动理解任意交叉表。
- 配置静态验证不能替代真实数据的 JOIN 命中率、重复键和合计验收。
- 当前没有特殊清洗规则市场；每条新增规则仍需样例、测试和版本说明。
- 若未来接收方主要是数据分析师而非业务人员，可单独评估更强的配置编辑器，但不能默认向所有用户开放。
